# ADR 001: dedicated AWG flow outbound in a unified Go module

Date: 2026-10-19. Status: accepted for the shared-core proof, **not approved as a
completed native-client architecture**.

Base: `origin/dev` at `ddde43635e957ebf042d92787489da72d3394019`.

## Inspected source

The existing Android path is `VpnProto.AWG -> AwgService ->
AmneziaVpnService -> protocol.awg.Awg -> protocol.wireguard.Wireguard`.
The protocol's `startVpn` receives the existing `VpnService.Builder` and a
protection callback. `GoBackend.awgTurnOn` still exists, but replacing it alone
would not configure domain capture, managed DNS, UI settings or lifecycle.
`client/cmake/android.cmake` links the existing AWG native dependency.

Apple's `PacketTunnelProvider+WireGuard.swift` creates a `WireGuardAdapter` and
maps split tunneling into allowed/excluded IPs. The pinned Apple submodule
`bdaf0b337b85c815e1dc462505455155b6cdfe79` already combines AWG and XRay in a Go
module. Adding another Go library to the extension is not the chosen solution.

Desktop networking is coordinated by the existing client and privileged
service; `service/server/router_linux.cpp` and the Windows daemon networking
must be integrated rather than replaced by an independent user-run process.
The existing Qt site controller performs `QHostInfo` lookups and stores IPs;
none of that path has been changed or relabeled as domain routing here.

## Alternatives evaluated

1. **AWG fork of the sing-box WireGuard endpoint.** The pinned sing-box
   transport depends on SagerNet's modified device/bind APIs: contextual device
   constructor, return-path integration, offset-bearing Send, reserved-byte
   mutation and endpoint resolver hooks. AWG v3 has a different constructor and
   bind interface. A wholesale module replacement is not compatible. The
   reserved-byte manipulation is particularly inappropriate for AWG's header
   obfuscation. Maintaining this fork would extend beyond a minimal parameter
   patch. No successful PoC of this alternative is claimed.
2. **Private TCP+UDP SOCKS bridge backed by AWG.** It would isolate runtimes if
   placed in another process, but adds listener authentication/exposure rules,
   UDP association management, another lifecycle and IPC/copy overhead. It is
   viable in principle; it has not been implemented or benchmarked.
3. **Dedicated sing-box outbound using AWG's flow stack. Chosen for the PoC.**
   The unchanged AWG module exposes an in-memory TUN plus TCP/UDP dial/listen
   API. The new `amneziawg` outbound registers into sing-box's outbound registry
   and converts routed flows into that stack. Real local TCP/UDP and shared-IP
   FakeIP tests pass. No server-side changes or vanilla-WG substitution occur.

## Ownership and data path

Target: native Amnezia VPN capture -> sing-box TUN/flow router -> protected
DIRECT sockets or AWG in-memory IP stack -> AWG device -> protected native UDP
socket -> existing AWG server. The in-memory AWG TUN is not an OS capture TUN
and does not compete with sing-box for application packets.

The session compiler targets one capture inbound and disables sing-box
auto-route. Native hosts must install/restore their routes and resolver state.
Native TUN ownership is **not yet implemented** on any feature platform.

DNS interception directs capture port 53 into sing-box. A/AAAA queries from the
capture inbound use FakeIP; internal domain resolution uses the explicit real
upstream. Reverse-IP identity guessing is disabled. Fake mappings are scoped
to an engine instance and are not persisted across reconnect. Numeric IPs and
unobservable domains use CIDR/default policy. CNAME/TTL, cache invalidation on
reconnect, DoH/DoT and FakeIP leak testing remain acceptance work.

The AWG endpoint must be resolved by native bootstrap before engine startup.
Only numeric endpoints enter this adapter. Its socket factory is mandatory;
an absent factory fails construction. DIRECT also requires native callbacks.
Both callbacks must preserve native OS lookup and exempt sockets from capture.
The core never installs a route to a selected router gateway. Resolver detours
are explicit; a loopback stub through AWG is rejected.

AWG-selected flows have no DIRECT retry. The local test verifies that loss of
the remote AWG peer does not reach the DIRECT observer. Full OS kill-switch
and always-on behavior are not tested. Native hosts must block captured IPv6
if they cannot support it; merely omitting an IPv6 route would leak traffic.

Startup creates the AWG flow stack/device, applies a redacted UAPI config and
opens its underlay socket. Sing-box scope cleanup closes the transport. Normal
shutdown must stop the engine, then restore native DNS/routes and release the
native VPN capture. Native crash cleanup and failed-start rollback are pending.
The adapter currently pins one endpoint per session and rejects datagrams from
other endpoints; native network changes require a session restart until bind
refresh and authenticated roaming are implemented and tested.

## Go runtime and ABI decision still required per host

The tests compile sing-box and AWG into **one Go module and runtime**. This
does not prove Android/iOS linking compatibility with existing libraries.
Android must either replace the existing AWG Go payload with a unified payload
or prove isolation in a service process that never loads another Go runtime.
An additional `.so` in the existing AWG process is not accepted.

iOS must integrate into the existing combined AWG/XRay Go payload, reconcile
its different dependency versions and measure Network Extension memory use.
The new core contains both AWG's gVisor module and SagerNet's gVisor module;
resource impact is unknown. Desktop service integration and native driver
ownership still need implementation. macOS remains regression-only.

## Update strategy

Pinned sing-box v1.14.3 (`7054cac5124465ffdb145870d7c01885566711b1`), AWG
v3.1.20260814 (`1b86b2ae0e493e7ea93f8c1a0f0cb6735b1551f1`), Go 1.27.1,
build tag `with_gvisor`. All transitive versions/checksums are in go.mod/go.sum.
No source patchset is applied. Update those pins deliberately; rerun real
TCP/UDP, IPv6, FakeIP egress, negative/fail-closed tests and every native build
before accepting an update. Full licenses/notices must accompany shipping.
